# database-controller

Provisions the data plane of RDS and Aurora PostgreSQL: the role, schemas,
grants and object ownership a service needs *inside* a database.

Creating the instance itself is a control-plane call that `provider-aws` or ACK
already covers. This is the part no AWS API can do.

## Install

```sh
helm install database-controller charts/database-controller \
  --namespace database-controller-system --create-namespace \
  --set serviceAccount.annotations."eks\.amazonaws\.com/role-arn"=arn:aws:iam::<acct>:role/<role>
```

The IAM role needs `rds-db:connect` on the admin user's dbuser ARN.

### Observe mode

A `DatabaseAccess` with `spec.mode: Observe` is planned against on every
reconcile and never applied: no statement runs, no finalizer is added, and
nothing is revoked on delete. Its `status.pendingStatements` / `status.pending`
and `Converged` condition say what Enforce would change. The chart needs no
setting for it; the mode is per resource.

### Why autoscaling is off

Leader election means exactly one replica reconciles however many are running.
Scaling out adds standbys, not throughput. The key exists for parity with the
chart layout this one follows.

### Why the CRD is in `templates/`, not `crds/`

This is the one deliberate departure from the `aws-load-balancer-controller`
chart layout.

Helm installs `crds/` once and then never upgrades or deletes it. A schema
change — a new field, a widened `engine` enum — silently never reaches a
cluster that already has the chart, and recovering means a manual
`kubectl apply` that somebody has to know to run. In `templates/` the CRD
upgrades with everything else, gated by `crds.install` for anyone who manages
CRDs separately.

`crds.keep` adds `helm.sh/resource-policy: keep` so an uninstall does not take
the CRD with it. Deleting the CRD deletes every `DatabaseAccess`, and each one
with `revokeOnDelete` set would run its revoke plan — an uninstall that
withdraws database access across the fleet.

## Generated files

`templates/crds.yaml` and `templates/rbac.yaml` are generated by
`hack/sync-chart.sh` from `config/`, which `controller-gen` owns. Edit the
kubebuilder markers in the Go source and run `make generate`; editing either
file directly means the chart drifts from what the controller actually needs,
and the failure is a permission error at runtime rather than anything review
would catch.
